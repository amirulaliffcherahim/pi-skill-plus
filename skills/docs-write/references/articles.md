# Articles and long-form drafts

Condensed from Matt Pocock's writing skills (`writing-fragments`, `writing-shape`, `writing-beats`; MIT, see NOTICE.md). These are interactive: they run as a conversation with the author, not as a one-shot draft.

## Two phases
1. **Explore (fragments)**: widen what could be written, with no structure yet.
2. **Exploit (shape or beats)**: the pile is fixed; commit to a structure and mine the pile to fill it.
Never mix them. Never edit the raw-material file in the exploit phase; it is read-only.

If the user gave no path, ask once where to save, then remember it.

## Explore: collect fragments
Interview the author relentlessly about the topic, and capture fragments from the first message on. A **fragment** is any piece that might survive into the article: a sharp sentence, a claim with a one-line reason, a vignette, a half-thought, a quote, a list that hangs together by feel, a confession. It must be readable by the author, not by a cold reader.
- The most valuable fragment is a **leading word**: a compact coinage or metaphor the whole piece hangs on. When the conversation circles an idea, push to name it.
- File format: a single H1 working title, then fragments separated by `---`. No headings in the body, no tags, no metadata.
- Append silently ("adding that"). Re-read the file from disk before each write; the author may have edited it. Never overwrite; only append, or edit one fragment in place on request ("cut the last one", "sharper").

## Exploit, option A: shape (paragraph by paragraph)
1. Read the pile end to end.
2. **Set prerequisites** with the author: what the reader already knows (grounded from the start).
3. Draft **2 or 3 candidate openings**, each implying a different thesis. Make the author pick or combine. The opening defines what the rest must do.
4. **Grow block by block.** Ask "given this opening, what does the reader need to hear next?" Pull from the pile, rework to fit, place it. Choose each block's form deliberately.
5. Append each agreed block immediately; never batch. Loop until the author says it is done.

## Exploit, option B: beats (choose your own adventure)
Same prerequisites step, then offer **2 or 3 candidate next beats** at each turn, each reachable from what is already grounded, each labelled with what it grounds. Write only the picked beat to the file, re-read the file, offer the next set. A beat is one move: a sentence, a short paragraph, or a vignette. If it needs five paragraphs and three headings it is two beats. The article ends when the journey is complete, not when the pile is empty.

## Grounding
Every **concept** must be grounded before a block leans on it: the reader either walked in knowing it or met it in an earlier block. The unit is the idea, not the word; a block can lean on an idea the reader lacks even with no jargon. Where a concept has a name, land the idea and the term together. Keep a running list of what is grounded; an ungrounded concept the next move needs is itself the answer to "what next?". Too much assumed shuts readers out; too much grounded inside drowns the opening, so settle it with the author.

## Conversational feel
Push back. Refuse weak transitions. Useful questions:
- What does this paragraph do for the reader that the previous one didn't?
- If I cut this, what breaks?
- Is this prose or a list? Why prose?
- This sentence does two jobs: split it or pick one.
- The opening promised X and we drifted to Y: re-thread it or change the opening.

## Format choices to argue out loud
Prose carries argument, lists carry parallel items. Callouts only for asides that would derail the main line. A table once the same shape repeats 3+ times with the same fields. Quote when the wording is the point, paraphrase when only the idea matters. Block for multi-line or runnable code, inline for a token.

## Gaps and scope
If the pile lacks something the article needs, name it: "we need an example here and the pile has none; give me one or we cut this." Out of scope: mining new fragments in the exploit phase, editing the raw file, publishing, platform formatting, frontmatter the author did not ask for.
